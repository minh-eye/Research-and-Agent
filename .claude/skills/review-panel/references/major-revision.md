# Major Revision 패널 — 연구 결정 토론

원고가 완성되기 전, 연구 도중 막힌 결정(분석 방법 선택, 결과 해석, 논문 프레이밍, 추가 조사 여부 등)에 대해 여러 관점의 독립 의견을 받아 하나의 권고안으로 종합한다.

출처: rev2agent `prompts/agent_workflow.md`의 "Major Revision" 트리거 (MIT, © 2026 Haebom Lee). rev2agent는 외부 LLM(GPT, Gemini 등)을 패널에 추가할 수 있지만, 이 하네스는 Claude 서브 에이전트만 사용한다. 외부 모델을 붙이려면 API 키와 자료 외부 전송에 대한 사용자 동의 절차를 따로 설계해야 한다.

## 언제 쓰는가

- 사용자가 "major revision"이라고 입력할 때
- "이 결정 어떻게 할까", "패널 의견 듣고 싶어", "막혔어" 등 연구 결정에 대한 다면 검토를 요청할 때

## 절차

1. **결정 사항 정리.** 사용자와 대화 맥락에서 무엇을 결정해야 하는지, 선택지는 무엇인지, 관련 자료(데이터 요약, 분석 결과, 초안 일부)는 어디 있는지 정리해 `_workspace/major_revision/{slug}/brief.md`에 쓴다. `{slug}`는 결정 내용을 2~4단어 영문 케밥 케이스로 줄인 것이다. 선택지가 불분명하면 사용자에게 한 번 확인한다.

2. **패널 구성.** 기본 패널은 Reviewer A(방법론), C(건축환경 도메인), D(회의적 독자) 3명이다. 결정 성격에 따라 바꾼다:
   - 비교·일반화 문제(어느 건물·계절 자료를 쓸지 등) → D 대신 또는 추가로 B
   - 서술·프레이밍 문제(논문 구성, 강조점) → A 대신 E
   패널 구성을 사용자에게 한 줄로 보여주고 진행한다.

3. **독립 의견 수집 (서브 에이전트, 병렬).** 각 리뷰어를 `Agent` 도구로 `run_in_background: true`, `model: "opus"`로 호출한다. 프롬프트에는 리뷰어 정의 파일 경로, `brief.md` 경로, 출력 경로, 아래 의견 형식만 넣는다. 다른 리뷰어의 의견은 넣지 않는다.

4. **종합.** 세 의견을 읽고 `_workspace/major_revision/{slug}/synthesis.md`에 쓴다:
   - 합의점: 모든 리뷰어가 동의한 것
   - 쟁점: 의견이 갈린 지점과 각 입장의 근거
   - 권고안: 하나의 추천과 그 근거. 표결이 아니라 근거의 강도로 정한다. 소수 의견이라도 결정적 반증이면 우선한다
   - 확인 필요 사항: 권고안을 확정하기 전에 확인해야 할 사실
   - 되돌릴 수 있는 첫 단계

5. **보고.** 권고안과 쟁점을 사용자에게 요약해 보여준다. 결정은 사용자가 한다.

## 의견 형식

```markdown
# Opinion {A/B/C/D/E} — {페르소나 이름}

## 입장
추천하는 선택지 한 줄.

## 근거
번호 목록. 각 근거가 어느 자료에 기대는지 밝힌다.

## 이 선택의 위험
추천안을 택했을 때 생길 수 있는 문제.

## 입장을 바꿀 조건
어떤 사실이 확인되면 다른 선택지를 추천할 것인가.

## 확신도
높음 / 중간 / 낮음 — 한 문장 이유.
```

## 주의

- 리뷰어 말투는 날카로워도 되지만, 권고안은 근거로만 정한다. 페르소나의 어조나 빠른 진행에 대한 선호가 결정을 좌우하지 않게 한다
- 독립 컨텍스트로 호출할 수 없는 환경이면(서브 에이전트 사용 불가) 오케스트레이터가 관점별로 직접 의견을 쓰되, 결과에 "독립 패널 아님 — 예비 의견"이라고 표시한다
